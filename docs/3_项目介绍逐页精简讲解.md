# 《项目介绍-A3双臂仿真》逐页精简讲解

本文按 `AI305_Project_a3/项目介绍-A3双臂仿真.pdf` 的11页顺序整理。目标是解释每页纲要的大意和它在整个项目中的位置，便于先建立全局印象；详细代码实现见 `local/2_仿真项目代码详细讲解.md`。

## 第1页：项目是什么

**这一页用一句话概括项目：这是一个围绕A3双臂机器人的仿真与策略学习平台。**  平台把 MuJoCo 物理仿真、A3 机器人模型和 LeRobot 数据/训练工具连接起来，让使用者能录制机器人示范、训练策略，再回到仿真中闭环测试。

- 研究任务是双臂抓取与饼干装盒。
- `2×5` 是把10块饼干放进两列、每列5块的目标盒；`2×10` 是20块、两列各10块。
- “可复现”指固定配置、随机种子和评测流程后，可以重复运行并比较结果。

**最重要的流程线是：示范数据 → 模型训练 → 仿真闭环评测。** 专家和遥操作可以生成示范；训练后的模型在评测时根据环境观测连续输出动作，环境再把执行结果反馈给模型。

## 第2页：平台由哪些部分搭成

**这页把系统按职责分成五层：仿真、控制、数据、学习和实验。** 这些不是互不相关的子项目，而是前一层给后一层提供接口和数据。

- **仿真层：** MuJoCo 计算机器人和物体的运动与接触；A3 的 URDF/网格资源描述机器人；YAML 保存场景参数。
- **控制层：** 把策略动作转成机器人可执行目标，并处理逆运动学（IK）、关节范围和动作变化速度等约束。
- **数据层：** 将相机、机器人状态、动作和任务指令按 LeRobot v3 格式组织，供训练和回放使用。
- **学习层：** 基于 LeRobot 工具微调 SmolVLA 或训练 ACT。
- **实验层：** 通过规则专家、人工遥操作和策略插件产生轨迹，并使用统一的闭环评测比较它们。

**理解这五层的连接方式，比记住库名更有用。** 学习算法并不直接驱动 MuJoCo 内部状态，它输出动作；控制层校验并执行动作；仿真层返回新的观测；评测层据此计算表现。

## 第3页：机器人、传感器和任务规模

**这一页给出了仿真的基本“量纲”：机器人有多少关节、策略能看到什么、运行频率是多少。** 这些设定共同决定数据格式和控制接口。

- 每条机械臂有7个机械关节和1个夹爪量，双臂拼起来是16维状态/关节动作。
- 策略可以接收前视、左腕和右腕三路 RGB 图像，分辨率为256×256。
- 控制频率是20 Hz，即每秒策略通常提交20次动作；物理仿真频率是1000 Hz，即每个控制周期里物理引擎会推进多个更细的步长。
- `2×5` 任务总计10块，通常分两批 `[5, 5]` 搬运；`2×10` 总计20块，目标盒两列各10块。

**控制频率与物理频率不能混为一谈。** 策略不必每个1毫秒物理步都重新推理；通常一次策略动作会在多个 MuJoCo 物理步中执行，这样既控制计算量，也保持物理模拟较细致。

## 第4页：从场景到评测的端到端流程

**这页展示项目的一次完整研究工作流。** 它从配置仿真任务开始，经过示范数据和模型训练，最后用闭环评测观察模型在新回合里的实际表现。

1. **场景与专家：** 读取 YAML 配置并初始化 MuJoCo 场景；通过规则专家或遥操作控制机器人。
2. **演示录制：** 同步记录三路图像、关节状态和实际执行动作，写成 LeRobot v3 数据集。
3. **模型训练：** SmolVLA 或 ACT 读取数据集进行训练，输出可部署的 checkpoint（模型检查点）。
4. **闭环评测：** 模型读取当前观测并预测动作，仿真执行后产生新观测和任务计分，再继续下一步。

**闭环评测和静态数据评估的区别在于，模型的动作会改变后续观察到的状态。** 如果一次抓取偏了，后续观测也会不同，模型必须在新的状态上继续决策，因此它评估的是完整的交互行为，而不只是离线预测是否接近示范动作。

## 第5页：规则专家是什么

**规则专家是手工设计的控制程序，可作为示范生成器和基线策略。** 它通常将任务拆成多个阶段，根据目标物体、机器人状态和接触信息，决定当前阶段的目标位置和夹爪动作。

典型顺序是：定位饼干 → 接近 → 闭合夹爪 → 抬升 → 搬运 → 放置 → 释放 → 验证结果。阶段状态机确保动作有先后关系，并可在抓取或放置失败时采取恢复动作。

**专家和纯视觉学习策略获得的信息不一样。** 专家可以直接读取仿真内部的物体位姿、接触、是否抬起或是否释放等真值；视觉策略通常从图像和规定的机器人状态中推断环境。因此专家成功不等于学习模型已经具备同等能力，它更像是老师、数据来源或规则基线。

## 第6页：域随机化做什么、不做什么

**域随机化是在每个回合开始时小幅改变仿真条件，避免策略只记住单一固定场景。** 例如盒子位置略微移动、目标盒略微旋转、相机视角轻微变化、光照或外观有变化。策略如果仍能完成任务，就可能学到对这些变化更稳健的行为。

- 随机化按 `basic`、`medium`、`advanced` 分档，强度逐步增加。
- 例子包括盒体 XY 位置扰动和目标盒偏航角扰动；相机、灯光和高级外观扰动也可按档位配置。
- `source_column`（来源列选择）和随机化强度是独立的实验因素；`2×10` 的 `first_grasp`（首轮抓取数量）也可以单独设置。
- PDF 明确列出的范围不包含质量、摩擦、尺寸或控制延迟随机化，因此不能把实验描述成覆盖了这些变化。

**随机化强度不是越高越好，而是测试模型面对变化时的稳健性。** 只有准确说明被随机化的因素，才能解释模型究竟在哪种变化下表现稳定；没有随机化的物理属性不能声称已验证。

## 第7页：录制示范数据

**这页用2×5任务说明如何用规则专家收集训练数据。** 采集程序反复尝试回合，成功时将观测和执行动作写进数据集；尝试次数可以大于最终成功 episode 数量。

PDF 中的命令示例：

```bash
MUJOCO_GL=egl python examples/collect_cookie_benchmark.py \
  --randomization-config configs/randomization.yaml \
  --episodes 100 --max-attempts 200 --seed-start 6001 \
  --root datasets/cookie_2x5_train \
  --repo-id local/cookie-2x5-train
```

- `--episodes 100`：目标是收集100个 episode，而非只试100次。
- `--max-attempts 200`：若部分专家回合失败，限制总尝试次数，防止无限采集。
- `--seed-start 6001`：指定一段可复现的随机种子起点。
- `--root`：本地数据集目录；`--repo-id`：数据集在 LeRobot 元数据中的标识。
- `MUJOCO_GL=egl`：在支持 EGL 的 Linux/服务器环境中选择无窗口渲染后端，适合批量采集。

**这类标准采集的重点是成功筛选和记录可追溯信息。** 数据不只是图像，还包含机器人状态、实际执行动作和任务信息；随机化配置与种子也应保留，便于复现实验。

## 第8页：微调 SmolVLA

**这页展示如何用前一页采集的数据微调 SmolVLA。** 模型以三路相机图像、关节状态和任务文本为输入，学习示范中的动作序列；训练产物以 checkpoint 形式保存，之后供仿真评测加载。

PDF 中的训练命令：

```bash
a3-sim train-smolvla \
  --root datasets/cookie_2x5_train \
  --repo-id local/cookie-2x5-train \
  --model models/smolvla_base \
  --output outputs/cookie_2x5_train/model \
  --steps 20000 --batch-size 8 --num-workers 2 \
  --lr 0.00005 --seed 1000 \
  --save-freq 2000 --device cuda
```

- `--root`、`--repo-id` 指向训练数据集；`--model` 是基座模型位置。
- `--steps` 是优化步数，`--batch-size` 是每步样本数，`--lr` 是学习率。
- `--seed` 控制训练随机性；`--save-freq` 控制检查点保存间隔。
- `--device cuda` 表示使用 NVIDIA GPU；输出目录保存训练结果。

**“训练运行完成”只表示优化流程结束，不表示机器人任务已经成功。** 需要用保存的检查点执行后续闭环评测，才能判断模型是否学会了在仿真中完成搬运任务。

## 第9页：单项闭环评测

**这页示范如何对某个已训练检查点进行固定协议的2×5评测。** 模型在20个新随机种子回合中运行，采用 `basic` 随机化和指定来源列，逐回合与仿真交互，结果保存成 JSON。

PDF 命令的核心参数含义：

- `--task 2x5`：选择10块饼干的任务。
- `--policy smolvla:<checkpoint>`：加载 SmolVLA 检查点作为策略。
- `--dataset-root`、`--repo-id`：提供训练数据集信息，供模型处理器和数据统计配置使用。
- `--profile basic --source-column 1`：选定随机化档位和来源列。
- `--episodes 20 --seed-start 13000`：运行20回合，从指定种子开始。
- `--inference-seed 13000`：控制模型推理过程中的随机性。
- `--max-steps 500`：每回合最多执行500个控制步。
- `--n-action-steps 8 --num-steps 25`：分别控制动作块的执行长度和 SmolVLA 推理相关设置。
- `--workers 1`：单 worker 执行；`--output` 指定评测结果文件。

**评测用“新种子”是为了减少只在训练初始条件上表现好的风险。** 单项评测回答的是“这个检查点在指定任务和随机化条件下表现如何”，不代表它已经在其它任务或更强随机化条件下验证。

## 第10页：六组网格评测

**这页把任务和随机化强度组合成六组系统测试。** 两个任务 `2×5 / 2×10` 乘以三个档位 `basic / medium / advanced`，每组20回合，所以总量是 $2\times3\times20=120$ 个评测回合。

网格评测 CLI 会为每种任务和档位生成相应配置，并复用指定 checkpoint、数据集和推理参数，分别保存各组结果。这样可以观察模型能力随任务规模增加、场景扰动增强时如何变化。

**如果训练检查点只用2×5数据训练，却拿去测2×10，2×10部分应被标记为迁移测试。** 它测试模型能否迁移到不同任务，不是2×10专门训练后的常规成绩；实验报告应把训练任务和被测任务分开陈述。

## 第11页：如何读评测结果

**主指标是回合结束时目标盒内的饼干数量，而不是过程中曾经达到的最高数量。** 2×5每回合范围为0–10，2×10范围为0–20；同时保留完整 `success` 标志，表示是否满足任务全部成功条件。

- **最终数量分数**反映回合结束时实际留在目标盒中的数量。
- **完整成功标志**比数量更严格，可能还要求布局、释放、稳定等条件满足。
- **500控制步约等于25秒仿真时间**，因为控制频率是20 Hz。2×10任务需要多次抓取，可能因步数上限而来不及完成四次搬运。
- **六项网格评测**由2个任务、3种随机化档位和每组20回合组成，便于横向比较。
- 训练完成、检查点文件生成或某次短程运行表现不错，都不等同于完整任务成功。

**结果解读要同时看分数、完整成功率、任务和随机化条件。** 例如一个模型可能平均搬入不少饼干，但很少达到完整成功条件；也可能只在 basic 条件下表现较好，在 advanced 条件下明显下降。两种现象对应不同结论。

## 全篇串联

**整份介绍讲的是一条可重复的机器人学习实验链路。** 先用仿真和规则专家产生示范，再把多模态演示组织成标准数据集，训练视觉动作策略，最后用固定种子和随机化协议进行闭环评测。

可以把项目的核心问题概括为：** 模型能否根据相机图像、机器人状态和任务指令，控制双臂把规定数量的饼干稳定地放进目标盒，并且在场景变化时仍然可靠？**

理解时建议记住三个界限：

- **专家示范不等于模型能力：** 专家可使用仿真真值，模型输入受策略接口限制。
- **训练完成不等于任务成功：** 是否完成需要闭环运行和环境判定。
- **仿真验证不等于真实硬件验证：** 这里展示的是可复现的仿真实验流程，不能直接当作真实机器人性能结论。
