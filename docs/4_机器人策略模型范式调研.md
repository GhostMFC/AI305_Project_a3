# 机器人策略模型范式调研：从 ACT、Diffusion/Flow、VLA 到 World Model + Planning

本文对照 `AI305_Project_a3/midterm.pdf` 中“机器人策略模型调研”的要求，围绕当前 A3 双机械臂 MuJoCo 项目调研四类机器人策略范式：ACT / Action Chunking、Diffusion / Flow-based Policy、Vision-Language-Action Model（VLA），以及 World Model + Planning。文中优先依据原论文、项目源码文档和 `midterm.pdf` 的明确要求；论文中的实验结果只代表论文自己的平台和协议，不代表 A3 项目的实验结果。

## 1. 先建立共同语言

机器人策略的本质是把“当前看到了什么”转换成“接下来要执行什么动作”。在离散时间 $t$，策略可以写成：

$$
\mathbf{a}_t \sim \pi_\theta(\mathbf{a}_t \mid \mathbf{o}_t, \ell),
$$

其中，$\mathbf{o}_t$ 是观测，$\ell$ 是可选的语言任务指令，$\mathbf{a}_t$ 是动作，$\pi_\theta$ 是带参数 $\theta$ 的策略模型；确定性策略也可以写成 $\mathbf{a}_t=\pi_\theta(\mathbf{o}_t,\ell)$。模型并不是只输出一个分数，而是要在真实或仿真环境中连续输出动作，使任务最终成功。

### 1.1 Observation、State、Action 的区别

观测是机器人能够获得的输入，状态是描述环境所需的完整变量，动作是机器人能够施加给环境的控制量。状态通常包含环境真值，而观测可能只是相机图像和本体感知，因此在视觉控制中通常只能近似地从观测恢复任务相关状态。

在 A3 项目中，学习策略主要使用三路 RGB 相机和关节状态；规则专家还可以读取 MuJoCo 中的物体位置、接触等仿真真值。项目常见输入包括：

| 项目                               | A3 中的含义                                                             |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `observation.images.front`       | 前视 RGB 图像                                                           |
| `observation.images.left_wrist`  | 左腕部相机 RGB 图像                                                     |
| `observation.images.right_wrist` | 右腕部相机 RGB 图像                                                     |
| `observation.state`              | 双臂关节和夹爪状态；完整模式通常为 16 维                                |
| 8D 左臂状态                        | 左臂 7 个关节加 1 个夹爪；部署时右臂需要保持 reset 后目标，不能简单补零 |
| `joint_position` 动作            | 16 维绝对关节目标，排列为左臂 8 维加右臂 8 维                           |
| `cartesian_delta` 动作           | 14 维笛卡尔位姿增量和夹爪指令，再由环境通过 IK 转换                     |

状态、动作和图像的维度只是接口层信息，不能据此判断模型已经学会任务。策略输出还要经过归一化反变换、动作合法性检查、关节限位、速度限制和底层控制器，最后才形成环境真正应用的动作。

### 1.2 A3 的闭环执行链路

A3 的核心不是一次前向推理，而是反复执行“观察、预测、执行、再观察”。完整闭环可以表示为：

```text
MuJoCo 环境状态
    ↓
Observation：三路图像、关节状态、可选任务文本
    ↓
Policy：规则专家 / ACT / SmolVLA / 其他策略
    ↓
Action：绝对关节目标或笛卡尔增量
    ↓
动作后处理、限位、IK、控制器执行
    ↓
环境状态变化和任务诊断
    ↓
成功判定、失败原因、下一次 Observation
```

真正应该优化的是固定评估协议下的闭环任务成功率，而不是单独优化训练 loss。A3 的任务成功还涉及入盒数量、槽位容差、稳定保持、边界覆盖和超时等条件；“程序没有报错”“模型输出了合法动作”“跑了若干控制步”都不等于任务成功。

## 2. 范式不是互斥的标签

机器人策略的“范式”至少有三个互相垂直的维度：输入条件决定模型看什么，动作表示决定模型输出什么，生成机制决定模型如何得到动作。将三者混为一个分类会误解方法之间的关系。

| 维度     | 典型选择                                           | 问题                                       |
| -------- | -------------------------------------------------- | ------------------------------------------ |
| 输入条件 | 图像、状态、语言、历史观测                         | 模型根据什么信息决定动作                   |
| 动作表示 | 单步动作、动作片段、离散动作 token、连续动作轨迹   | 模型一次输出多少控制量、以什么数值形式输出 |
| 生成机制 | 回归、CVAE、Diffusion、Flow Matching、自回归、规划 | 如何从条件得到一个或多个合理动作           |
| 决策结构 | 端到端、分层策略、世界模型预测加规划               | 是否显式预测子任务、未来状态或回报         |

因此，ACT 主要强调“动作分块加 Transformer”；Diffusion Policy 主要强调“通过去噪生成连续动作分布”；SmolVLA 主要是“视觉语言条件的 VLA”，同时使用动作分块和 flow matching。一个 VLA 完全可以使用 diffusion 或 flow action head，World Model 也可以和 VLA、规划器或低层控制器组合。

## 3. 范式一：ACT / Action Chunking with Transformers

ACT 的核心思想是让模型根据当前观测一次预测一段未来动作，而不是每次只预测一个动作。它把长任务拆成一串短期动作片段，并用更频繁的观测和动作融合缓解行为克隆的误差累积。

### 3.1 为什么单步行为克隆容易失败

普通行为克隆把示范数据中的每个时刻当作监督样本，训练：

$$
\mathcal{L}_{\mathrm{BC}}(\theta)=\mathbb{E}_{(\mathbf{o}_t,\mathbf{a}_t)\sim\mathcal{D}}
\left[\|\pi_\theta(\mathbf{o}_t)-\mathbf{a}_t\|^2\right].
$$

训练时模型看到的是专家轨迹附近的状态，部署时自己的微小动作误差会把机器人带到示范数据没有覆盖的状态；之后的预测误差继续累积，这就是 compounding error。抓取、接触和放置任务尤其敏感，因为几毫米的位置误差就可能导致抓空、碰撞或释放失败。

单步回归还有一个问题：同一个观测可能对应多种合理轨迹，例如从目标左侧接近或从右侧接近。用单个均值动作拟合多种模式，可能得到任何一种轨迹都不真正合理的“平均动作”。

### 3.2 Action Chunking 如何改变问题

ACT 将单步策略改写为动作片段策略：

$$
\pi_\theta(\mathbf{a}_{t:t+K-1}\mid \mathbf{o}_t),
$$

其中 $K$ 是 chunk size，$\mathbf{a}_{t:t+K-1}$ 表示从时刻 $t$ 开始的 $K$ 个动作。模型输出的张量形状可以理解为 $K\times d_a$，其中 $d_a$ 是动作维度；A3 的 16D 绝对关节目标模式下就是一段 $K\times16$ 的动作目标。

动作分块有三层作用。第一，它把模型要学习的有效决策次数减少，连续抓取或搬运动作可以作为一个短序列共同建模。第二，Transformer 可以在片段内部建模动作之间的时间相关性，避免每个动作独立预测造成抖动。第三，片段可以表达演示中的暂停、接触调整和连续修正，这些行为用单步无记忆回归不容易表示。

### 3.3 Temporal Ensemble 为什么有用

只在每 $K$ 步重新观察一次会造成新旧动作片段突然切换，因此 ACT 论文还提出 temporal ensemble。策略在每个时刻都重新预测动作片段；对于同一个未来执行时刻，多个历史观测会产生多个预测，再用加权平均融合：

$$
\mathbf{a}_t=\frac{\sum_i w_i\,\hat{\mathbf{a}}_t^{(i)}}{\sum_i w_i},
\qquad w_i=\exp(-m i),
$$

其中 $\hat{\mathbf{a}}_t^{(i)}$ 是第 $i$ 个预测片段对执行时刻 $t$ 的预测，$m$ 控制新旧预测的权重衰减。这里融合的是“对同一个时刻的多个预测”，不是简单把相邻时刻动作做平滑平均。

Temporal ensemble 的收益是动作更平滑、观测更新更连续；代价是每个控制周期都需要推理，计算量明显高于只在 chunk 边界推理。A3 项目中的 `n_action_steps=1` 才接近每步重预测与时间集成的语义；默认执行多个动作后再预测，不能自动称为 temporal ensemble。

### 3.4 ACT 的 CVAE 机制

ACT 使用条件变分自编码器建模示范动作片段的变化。训练时，CVAE 编码器接收动作片段和部分状态，推断潜变量 $\mathbf{z}$；解码器接收图像、状态和 $\mathbf{z}$，重建动作片段：

$$
\mathcal{L}_{\mathrm{ACT}}=
\mathcal{L}_{\mathrm{recon}}+
\beta D_{\mathrm{KL}}\left(q_\phi(\mathbf{z}\mid \mathbf{a}_{t:t+K-1},\bar{\mathbf{o}}_t)\,\|\,\mathcal{N}(\mathbf{0},\mathbf{I})\right).
$$

其中，$\mathcal{L}_{\mathrm{recon}}$ 是动作片段重建误差，$q_\phi$ 是训练期编码器，$\beta$ 控制潜变量正则强度，$\bar{\mathbf{o}}_t$ 表示不含图像的状态信息。推理时不再使用编码器，而是把 $\mathbf{z}$ 设为先验均值，通常为零，再由解码器根据当前图像和状态生成动作。

CVAE 不是为了让机器人在每次部署时随机乱试，而是让训练过程承认“同一观测下示范可能有多种动作风格”。将潜变量约束到标准高斯先验后，模型可以在训练时学习动作片段的变化，同时在确定性部署时使用稳定的默认风格。

### 3.5 ACT 的训练与推理流程

ACT 的训练流程是从成功示范中截取窗口，并让 Transformer 同时处理多视角视觉特征、关节状态和动作序列。典型流程如下：

1. 从示范中取当前观测 $\mathbf{o}_t$ 和未来 $K$ 步动作 $\mathbf{a}_{t:t+K-1}$。
2. 用 CVAE 编码器从动作片段推断 $\mathbf{z}$。
3. 视觉编码器提取图像特征，Transformer 编码器融合图像、状态和潜变量。
4. Transformer 解码器生成 $K$ 个连续动作目标。
5. 用动作重建损失和 KL 正则更新网络。
6. 部署时只保留策略解码路径，按重预测频率消费动作片段。

ACT 论文原始设置使用多视角 RGB、双臂关节状态和绝对关节位置动作；论文平台和 A3 并不相同。A3 当前文档中的 ACT 适配是三路相机、8D 或 16D 状态/动作，并默认一次预测 50 个动作、执行 8 个后重新预测，因此不能直接把论文里的相机数量、自由度、控制频率或结果照搬过来。

### 3.6 ACT 的优势、局限与 A3 优化方向

ACT 最适合“示范质量较高、任务主要是连续操作、需要动作连贯性”的场景。它的优势是模型结构和训练目标相对清晰，动作片段能减少单步抖动，绝对关节目标与底层位置控制器天然匹配，并且 A3 已经提供 ACT 的训练与部署入口。

ACT 的主要局限是它仍然是行为克隆，无法自动获得示范之外的纠错能力；chunk 太长会降低遇到异常时的反应速度，chunk 太短又会增加推理开销并可能重新出现抖动；示范场景过于单一时，模型可能只记住固定路径；8D 左臂策略还需要正确处理右臂保持目标。

对 A3 最有价值的 ACT 实验是单因素比较 `chunk_size` 与 `n_action_steps`，保持数据、检查点和评估 seed 不变；随后再比较加入失败恢复示范、多布局成功示范和针对失败阶段采集的数据。每次实验都要同时记录完整成功率、入盒数量、首次抓取时间、动作越界、失败阶段和推理耗时，不能只看训练 loss。

## 4. 范式二：Diffusion Policy 与 Flow-based Policy

Diffusion/Flow 策略不是直接回归一个唯一动作，而是学习条件动作分布，再从噪声或简单基分布逐步生成一段连续动作。它特别适合“同一观测存在多条合理轨迹”的操作任务，但推理通常比普通回归更昂贵。

### 4.1 从确定性回归到条件分布

如果只学习一个函数 $\hat{\mathbf{a}}=f_\theta(\mathbf{o})$，模型往往趋向于输出多种示范的平均值。生成式策略改为学习：

$$
p_\theta(\mathbf{A}_t\mid \mathbf{O}_t),
$$

其中，$\mathbf{O}_t$ 可以包含最近若干帧图像和状态，$\mathbf{A}_t=[\mathbf{a}_t,\ldots,\mathbf{a}_{t+H-1}]$ 是未来动作序列。这样模型不必把左绕、右绕、快接近、慢接近等模式压成一个均值，而可以从条件分布中采样一条完整且内部一致的轨迹。

### 4.2 Diffusion Policy 的第一性原理

Diffusion Policy 在训练时把真实动作序列逐渐加噪，在不同噪声等级下要求网络预测噪声；在推理时从高斯噪声开始，反复去噪得到动作序列。简化的训练目标可以写为：

$$
\mathcal{L}_{\mathrm{diff}}=
\mathbb{E}_{\mathbf{O},\mathbf{A}^0,k,\boldsymbol{\epsilon}}
\left[
\left\|\boldsymbol{\epsilon}-
\epsilon_\theta(\mathbf{O},\mathbf{A}^0+\boldsymbol{\epsilon},k)
\right\|^2
\right],
$$

其中，$\mathbf{A}^0$ 是示范动作序列，$k$ 是噪声等级，$\boldsymbol{\epsilon}$ 是加入的高斯噪声，$\epsilon_\theta$ 是条件噪声预测网络。推理时从 $\mathbf{A}^K\sim\mathcal{N}(\mathbf{0},\mathbf{I})$ 出发，依次得到 $\mathbf{A}^{K-1},\ldots,\mathbf{A}^0$。

这个过程可以直观理解为：网络学习“在当前观测下，动作序列分布中哪些方向更像示范”；反复沿着这个方向场把随机序列拉回可执行轨迹。随机初始噪声和采样过程使其能够表达多峰分布，而不是只学习一个均值动作。

### 4.3 Receding Horizon 与三个长度参数

Diffusion Policy 通常把观测长度、预测长度和实际执行长度分开。设 $T_o$ 是观测历史长度，$T_p$ 是一次预测的动作长度，$T_a$ 是在下一次观测前实际执行的动作长度，则有：

$$
\mathbf{O}_t=\mathbf{o}_{t-T_o+1:t},
\qquad
\mathbf{A}_t=\mathbf{a}_{t:t+T_p-1},
\qquad
\text{execute }\mathbf{a}_{t:t+T_a-1}.
$$

每执行 $T_a$ 步就重新观察、重新生成动作片段，这就是 receding-horizon control。$T_p$ 越长，动作序列的整体一致性通常越好，但预测越难；$T_a$ 越长，推理负担越低但闭环纠错更慢；$T_a$ 越短，反应更及时但推理成本更高。

这三个变量不能与训练步数混淆。A3 文档中的训练 `--steps` 是优化更新次数，评测 `--max-steps` 是控制步预算，`chunk-size` 是动作预测长度，`n-action-steps` 是实际消费长度；它们描述的是不同层次的时间尺度。

### 4.4 Flow Matching 与 Diffusion 的关系

Flow matching 和 diffusion 都是生成式动作策略，但训练对象和采样路径不同。Diffusion 通常学习不同噪声等级下的 score 或噪声预测，并执行离散去噪；flow matching 直接学习从简单噪声分布流向数据分布的向量场，在推理时通过数值积分沿向量场移动。

以 SmolVLA 中的 flow matching action expert 为例，设真实动作片段为 $\mathbf{A}$，噪声为 $\boldsymbol{\epsilon}$，插值时间为 $\tau\in[0,1]$，中间状态可写为：

$$
\mathbf{A}^{\tau}=\tau\mathbf{A}+(1-\tau)\boldsymbol{\epsilon},
$$

模型学习向量场 $\mathbf{v}_\theta(\mathbf{A}^{\tau},\mathbf{o})$，使它接近从噪声状态走向数据状态的目标方向。直观上，diffusion 更像一串带噪声的去噪步骤，flow matching 更像学习一条连续运输路径；二者都能生成连续动作片段，但不能把两者的超参数和推理步数直接互换。

### 4.5 Diffusion/Flow 的优势与局限

这类模型的第一项优势是表达多模态动作分布；当同一目标存在多种抓取方向、绕障路线或双臂协作轨迹时，生成式表示比单一均值回归更自然。第二项优势是直接生成动作序列，能够联合建模相邻动作的时间一致性。第三项优势是位置控制下的动作片段通常比较平滑，适合由底层控制器追踪。

主要局限是推理需要多次去噪或数值积分，实时性受到采样步数、动作片段长度和视觉编码开销影响；模型的归一化、噪声 schedule、采样器和动作执行长度都需要调节；如果数据本身只有一种狭窄行为，多模态建模的额外成本未必带来收益；生成动作仍可能越界、碰撞或无法恢复，生成式并不等于具备安全性。

Diffusion Policy 论文报告了多个仿真和真实操作基准上的提升，但这些结果基于论文指定的数据、机器人和评估协议，不能直接推断 A3 的装盒成功率。论文还强调，推理迭代数可以通过 DDIM 等方法减少，但速度和性能仍需在目标任务上单独测量。

### 4.6 对 A3 的接入与实验建议

A3 当前仓库已有 ACT 和 SmolVLA 接口，但没有现成的 Diffusion Policy 适配器，因此接入成本明显高于先跑 ACT。至少需要完成三路图像编码、观测历史组织、8D/16D 动作归一化、绝对关节或笛卡尔动作语义适配、检查点处理器保存，以及与统一 benchmark 的闭环连接。

如果要引入 Diffusion Policy，最小可行路线是先使用同一批成功示范和同一动作空间，实现一个仅预测动作片段的策略，再固定模型比较采样步数、$T_a$ 和不同 chunk 长度对成功率、推理耗时和失败阶段的影响。只有当 A3 的失败证据显示单峰回归无法表达多条有效轨迹时，才有充分理由承担生成式策略的复杂度。

## 5. 范式三：Vision-Language-Action Model

VLA 的核心是把视觉、语言、本体状态和机器人动作放进一个统一的条件建模框架，使机器人不仅能回答“怎么动”，还可以理解“要对哪个对象做什么”。VLA 是输入与知识范围的范式，不规定唯一的动作生成器，因此可以结合离散 token、自回归、Diffusion 或 Flow Matching。

### 5.1 VLA 解决了什么问题

传统单任务策略通常学习“固定观测到固定动作”的映射，任务指令可能藏在数据集名称或代码配置里；VLA 显式接收语言指令，把任务目标作为条件输入：

$$
\mathbf{A}_t\sim \pi_\theta(\mathbf{A}_t\mid
\mathbf{I}_t^{1:n},\mathbf{q}_t,\ell),
$$

其中，$\mathbf{I}_t^{1:n}$ 是多路图像，$\mathbf{q}_t$ 是关节或本体状态，$\ell$ 是自然语言任务。这样同一组视觉状态在不同指令下可以产生不同动作，例如“把红色饼干放入目标盒”和“把蓝色饼干放回源盒”。

语言并不会凭空创造控制能力。若训练数据只有一条固定装盒指令，模型可能把文本当成常量，无法证明语言泛化；要验证语言作用，必须设计不同目标、不同对象或不同子任务的指令，并保持视觉和动作条件可比较。

### 5.2 VLA 的基本结构

一个典型 VLA 包含视觉编码器、语言模型或多模态 Transformer、状态投影层和动作头。图像被切成视觉 token，文本被编码成语言 token，关节状态经过线性投影，之后由共享或交互式 Transformer 融合；动作头再把融合特征转换为离散动作 token 或连续动作片段。

OpenVLA 代表一种大规模、开放的 VLA 路线：它基于视觉编码器和语言模型，把连续动作的每一维离散到若干 bins，再把动作当作语言模型需要预测的 token，使用 next-token prediction 训练。离散动作 token 便于复用语言模型训练基础设施，但会受到量化精度、自回归延迟和动作序列长度的影响。

SmolVLA 代表一种更轻量的路线：它使用小型预训练 VLM 处理图像、任务文本和状态，再用独立的 flow matching action expert 生成连续动作片段；动作专家与 VLM 特征通过交叉注意力和动作 token 的自注意力交互。该设计把语义感知和精细连续控制分开，同时保留端到端条件关系。

### 5.3 SmolVLA 的动作生成和异步推理

SmolVLA 的 action expert 不是普通线性回归，而是根据 VLM 特征对动作片段进行 flow matching 生成。推理时，从噪声动作开始，通过若干 flow 迭代得到连续动作 chunk；`num_steps` 表示一次动作生成内部的 flow 推理迭代次数，而不是训练更新次数，也不是环境控制步数。

SmolVLA 还提出异步推理，把“获取观测并请求策略生成”与“消费已有动作队列”解耦。机器人不必等待当前 chunk 完全耗尽才开始下一次推理，而是在队列低于阈值时提前请求新 chunk，再把新旧队列合并。这样可以减少推理空档并允许策略部署在远程 GPU 上，但会引入队列阈值、网络延迟、重复观测过滤和动作合并等系统变量。

A3 当前项目文档提供 SmolVLA 的训练、检查点和部署流程，但论文中的异步推理方案不能自动视为 A3 已启用。评测时必须明确是否使用固定 chunk 消费、异步队列、动作平滑、右臂规则锚定或其他后处理，否则不同配置不能直接比较。

### 5.4 VLA 的优势

VLA 的第一项优势是语言条件带来的任务组合和目标选择能力，尤其适合多对象、多任务和需要指明目标的场景。第二项优势是预训练视觉语言模型提供了互联网规模的语义和视觉先验，配合多机器人、多场景示范有机会改善跨物体、跨背景和跨任务泛化。第三项优势是 VLA 可以统一训练文本输出、视觉理解、动作 token 和连续动作专家，形成更通用的策略接口。

VLA 的优势高度依赖数据规模、数据多样性和本体适配。OpenVLA 的大规模论文结果、SmolVLA 的多任务结果以及更大模型的泛化表现，不等于把小规模 A3 数据送入基座就能直接获得同样能力。A3 的 8D 左臂数据、三路相机、双臂任务和动作保持逻辑都需要被明确适配。

### 5.5 VLA 的局限与 A3 风险

VLA 的主要代价是训练、显存和推理复杂度通常高于专门的 ACT；视觉 token、语言 token、状态投影、processor、归一化统计和动作头之间任何一个不一致，都可能出现“loss 正常但闭环空抓”的问题。大模型的语言能力也可能掩盖控制能力不足，必须用闭环轨迹和任务指标检查。

对 A3 而言，最危险的错误包括把 8D 模型当作 16D 模型部署、错误重建右臂动作、混用不同数据集的 processor 统计量、把 `num_steps` 当成控制步、把固定 prompt 的结果写成语言泛化，以及把 SmolVLA 基座当成已经学会 A3 装盒。项目现有 SmolVLA 手册明确要求审计三路图像、8D/16D 维度、检查点处理器和闭环动作链路。

## 6. 范式四：World Model + Planning

World Model + Planning 的核心不是直接记住“看到什么就做什么”，而是先学习或利用一个能够预测未来状态、观测和回报的环境模型，再在模型中想象候选动作后选择更好的动作。它属于显式预测未来的模型式控制路线，与 ACT、Diffusion 和 VLA 的端到端动作生成形成对照。

### 6.1 从策略映射到环境预测

直接策略学习的是：

$$
\mathbf{a}_t=\pi_\theta(\mathbf{o}_t).
$$

世界模型学习的是状态转移和任务结果：

$$
\hat{\mathbf{s}}_{t+1}=f_\phi(\mathbf{s}_t,\mathbf{a}_t),
\qquad
\hat{r}_t=g_\phi(\mathbf{s}_t,\mathbf{a}_t),
$$

其中，$f_\phi$ 预测执行动作后的下一状态，$g_\phi$ 预测奖励或任务进展，$\phi$ 是世界模型参数。规划器在候选动作序列 $\mathbf{A}_{t:t+H-1}$ 上展开模型：

$$
\hat{\mathbf{s}}_{t+k+1}=f_\phi(\hat{\mathbf{s}}_{t+k},\mathbf{a}_{t+k}),
$$

再根据累计预测回报、碰撞惩罚、动作平滑度和终点目标选择序列，通常只执行第一步或前几步，然后重新观测和规划，这就是模型预测控制式 receding horizon。

### 6.2 学习式 World Model 的典型结构

在视觉任务中，直接预测每个像素的未来代价很高，因此常见做法是把图像编码为潜变量 $\mathbf{z}_t$，用循环状态 $\mathbf{h}_t$ 表示历史，再学习动作条件下的潜在转移：

$$
\mathbf{h}_t=F_\phi(\mathbf{h}_{t-1},\mathbf{z}_{t-1},\mathbf{a}_{t-1}),
\qquad
\mathbf{z}_t\sim q_\phi(\mathbf{z}_t\mid\mathbf{h}_t,\mathbf{x}_t).
$$

模型还可以预测未来潜变量、奖励、回合是否继续，并通过重建当前观测约束潜变量保留任务相关信息。DreamerV3 是这类路线的代表性工作：它在潜在空间中想象未来轨迹，由 actor 选择动作、critic 评价回报，并在多种任务上使用统一配置进行强化学习。这个例子说明了世界模型如何把昂贵的真实交互转化为潜在空间中的大量想象，但 DreamerV3 的论文实验不能直接视为 A3 装盒方案。

### 6.3 Planning 的几种实现

规划器可以是采样型、优化型或策略型。采样型方法从动作分布中提出许多候选序列，用世界模型滚动预测并挑选得分最高者；优化型方法通过梯度或交叉熵方法迭代改进动作序列；MPC 型方法只执行最优序列的前几步，然后重新规划。也可以让一个低层策略生成候选动作，把规划器限制在策略分布附近，从而兼顾可行性和搜索能力。

World Model + Planning 还可以与高层语言模型结合：语言模型把“完成装盒”拆成“选择目标饼干、接近、夹取、搬运、释放、确认稳定”等子任务，世界模型和低层控制器负责在每个子任务内预测与执行。此时语言模型负责语义规划，世界模型负责物理后果预测，策略或控制器负责连续动作。

### 6.4 优势

World Model + Planning 的最大优势是可以显式比较“做这个动作会发生什么”，因此适合长时域、稀疏奖励和需要避免碰撞的任务。它还可以在执行前评估多个候选轨迹，提供一定的可解释性；如果模型足够准确，真实机器人交互次数可能少于纯模型自由探索。

对于 A3，MuJoCo 已经提供一个可调用的物理仿真环境，因此可以把环境当作已知 simulator，先研究基于仿真的 MPC、轨迹采样或规则规划，而不必立即训练视觉世界模型。这个路线可用于生成更安全的动作候选、提供专家数据或分析 ACT/SmolVLA 失败后的恢复动作。

### 6.5 局限与 A3 适配难点

世界模型的根本风险是模型偏差：如果预测的接触、夹爪摩擦、饼干碰撞或盒内稳定状态不准确，规划器可能反复选择在模型中高分、在真实环境中失败的动作。视觉世界模型还要同时学习遮挡、物体身份、双臂接触和任务进度，数据与计算成本很高。

A3 当前仓库没有现成的 World Model + Planning 策略适配器，也没有一个与学习策略统一的奖励模型和规划接口。若直接从图像训练世界模型，工作量会明显超过 ACT/SmolVLA 基线；若直接使用 MuJoCo 真值规划，又会与纯视觉策略的输入条件不公平。因此更合理的课程项目路线是把它作为扩展方案：先使用 simulator 生成候选或失败恢复数据，再考虑学习潜在动力学模型。

## 7. 四类范式的横向比较

不同范式的关键区别可以概括为“是否直接输出动作、是否显式表达动作分布、是否使用语言条件、是否预测未来环境”。

| 维度                 | ACT                          | Diffusion / Flow Policy      | VLA                                      | World Model + Planning                |
| -------------------- | ---------------------------- | ---------------------------- | ---------------------------------------- | ------------------------------------- |
| 主要输入             | 图像、状态                   | 图像、状态及可选历史         | 图像、状态、语言                         | 状态或图像历史、动作，可能含语言目标  |
| 主要输出             | 连续动作片段                 | 从生成分布采样的连续动作片段 | 离散动作 token 或连续动作片段            | 候选动作、未来状态/回报，最终输出动作 |
| 动作分块             | 核心机制                     | 常见机制                     | 常见机制                                 | 可结合，但不是必须                    |
| 多模态动作           | CVAE 潜变量有限表达          | 生成式表达能力强             | 取决于动作 token、diffusion 或 flow head | 通过多个候选轨迹表达                  |
| 语言条件             | 通常没有                     | 可选                         | 核心特征                                 | 可作为高层规划输入                    |
| 是否显式预测未来环境 | 否                           | 否，主要生成动作             | 通常否；高层 VLA 可生成子任务            | 是                                    |
| 闭环响应             | 由重预测频率决定             | 由执行长度和采样速度决定     | 由 chunk、异步推理和控制器决定           | 由规划周期和模型推理速度决定          |
| 数据需求             | 成功示范即可起步             | 多样动作分布和较稳定示范     | 大规模多任务、多模态数据更有利           | 状态转移、奖励或交互数据              |
| 计算成本             | 相对较低                     | 采样和视觉编码成本较高       | 从轻量到数十亿参数差异很大               | 训练模型加在线规划，整体较高          |
| A3 当前状态          | 已有训练/部署接口            | 尚无现成适配器               | SmolVLA 已有接口                         | 尚无现成适配器                        |
| 首选研究问题         | chunk 和恢复数据是否改善闭环 | 多模态轨迹是否值得采样成本   | 语言/多任务数据是否改善泛化              | 预测式规划是否改善恢复与安全性        |

这张表不能用来简单判定谁“最先进”。如果任务是单一的 2×5 装盒、示范量有限且项目时间有限，ACT 的接入风险最低；如果失败证据显示多种抓取路径都合理，Diffusion/Flow 更值得尝试；如果需要多对象、多指令和跨任务泛化，VLA 更有研究价值；如果主要问题是长时域规划、碰撞规避和失败恢复，World Model + Planning 才有明确动机。

## 8. 对 A3 项目的具体选择建议

当前最稳妥的项目路线是先以规则专家验证环境和数据，再以 ACT 建立学习基线，之后把 SmolVLA 作为多模态对照，最后根据失败模式决定是否接入 Diffusion 或 World Model。

### 8.1 第一阶段：建立公平基线

第一阶段应该固定任务、随机化、控制频率、最大步数、成功判定、数据版本和评估 seed。规则专家用于确认环境和成功判定；ACT 用指定示范训练和统一 benchmark 评估；SmolVLA 必须使用匹配的 processor、状态/动作维度和相机键。

报告时应明确：A3 的现有数据约为 100 回合、42,681 帧、20 FPS、三路 256×256 RGB、8D 左臂状态/动作；这只是当前指定数据契约，不应误写成完整双臂 16D 数据。8D 模型部署时右臂需要保持 reset 后目标，这是接口行为而不是让模型预测一个全零右臂。

### 8.2 第二阶段：围绕失败原因做单因素实验

如果 ACT 主要在抓取前定位偏移，优先增加多布局和多相机覆盖；如果抓取成功但搬运中掉落，检查 chunk 长度、动作平滑和执行频率；如果放置后槽位不稳定，采集释放后的稳定与恢复示范；如果遇到失败状态就无法继续，加入带失败恢复的示范或引入局部规划器。

如果 SmolVLA 的离线误差低但闭环失败，优先排查图像键、processor、归一化、8D 到 16D 拼接、动作时域和推理迭代数，而不是立刻增大模型。若固定 prompt 下不同语言写法没有改变行为，也不能声称已经验证语言泛化。

### 8.3 第三阶段：判断是否值得引入更复杂范式

是否引入 Diffusion/Flow，应该由“单一动作回归不能同时表达多个有效轨迹”的证据驱动；是否引入 World Model，应该由“主要瓶颈是长时域规划、碰撞规避或失败恢复”的证据驱动；是否扩大 VLA，应由“任务确实包含多指令、多对象或跨场景泛化需求”的证据驱动。

不应因为模型名称更新或参数量更大就直接声称性能会提升。每次复杂化都要和 ACT 基线在同一数据、同一动作接口、同一评估协议和相同计算预算下比较，并保留失败结果，才能判断额外机制是否真的产生了收益。

## 9. 推荐的实验记录格式

可复现的机器人策略研究不仅要保存模型，还要保存模型所处的实验条件。每轮实验至少应记录：

| 字段              | 内容                                                                        |
| ----------------- | --------------------------------------------------------------------------- |
| `experiment_id` | 唯一实验名称和父实验                                                        |
| 代码与配置        | Git 提交、工作区 diff、命令行参数                                           |
| 数据              | 数据集路径、版本、回合数、8D/16D、相机键                                    |
| 模型              | 范式、检查点路径、动作空间、processor 来源                                  |
| 时序              | chunk size、观测历史、实际执行长度、推理迭代数                              |
| 环境              | 任务、随机化、控制频率、最大步数、成功阈值                                  |
| 结果              | 成功率、入盒数量、步数、推理耗时、失败类别                                  |
| 诊断              | trace、视频、截图、`raw_action`、`processed_action`、`applied_action` |
| 解释              | 本轮假设、实际修改、是否支持假设、下一步候选                                |

这样才能区分“模型结构改进”“数据覆盖改进”“部署参数改变”和“评估协议改变”分别造成了什么影响，也能避免把一次固定 seed 的成功写成普遍成功率。

## 10. 结论

ACT、Diffusion/Flow、VLA 和 World Model + Planning 解决的是机器人策略问题的不同侧面：ACT 解决动作片段的时序连贯和行为克隆误差，Diffusion/Flow 解决连续多模态动作生成，VLA 解决视觉语言条件和跨任务泛化，World Model + Planning 解决未来预测、长时域决策和显式规划。

对当前 A3 项目，最有依据的优先级是：先用规则专家确认环境，再用已有 ACT 接口建立可复现基线；随后用 SmolVLA 研究多模态输入和轻量 VLA；只有在闭环失败分析提供明确证据后，才投入 Diffusion/Flow 或 World Model + Planning。最终评价必须回到 MuJoCo 闭环任务成功，而不能用训练 loss、离线动作误差或论文中的其他平台成绩替代。

| Diffusion Policy  | 通过逐步去噪从噪声生成条件动作序列的策略           |
| Flow Matching     | 学习从噪声分布流向动作分布的向量场                 |
| VLA               | 同时使用视觉、语言和动作建模的机器人策略           |
| Action Expert     | VLA 中专门负责连续动作生成的子网络                 |
| Receding Horizon  | 预测一段、执行前几步、重新观察并再次规划           |
| World Model       | 预测动作导致的未来状态、观测或回报的环境模型       |
| MPC               | 每次规划一段控制序列，只执行开头部分后重规划       |
| Closed-loop       | 动作会改变环境，策略根据新观测持续修正             |
